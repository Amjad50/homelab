# Backup System

The backup system is generated by `common/modules/service-registry.nix` and uses NixOS `services.restic.backups` under the hood. Backup definitions live alongside the services that depend on them, so the service registry is the source of truth for:

- Restic paths
- PostgreSQL dump inputs
- Custom backup hooks
- Custom restore hooks
- Restore metadata exposed at `/etc/homelab/services.json`

## Current Flow

Each backup group becomes:

- one `services.restic.backups.<group>` definition
- one `restic-locked-<group>.service` wrapper for serialization
- one `restic-locked-<group>.timer`
- one restore sentinel at `/var/lib/homelab/restored/<group>`
- one `homelab-backup` CLI entry point

The current `home` machine uses two groups:

- `default` for normal services
- `immich` for the large media restore path, with `restoreAutoStart = false`

## CLI

```bash
homelab-backup list
homelab-backup restore default
homelab-backup backup default
homelab-backup restore immich
```

`homelab-backup` supports:

- `list` to show restore state, live backup/restore service state, and the latest snapshot metadata
- `restore <group>` to stop the group, restore files and databases, run hooks, and restart services
- `backup <group>` to trigger the serialized `restic-locked-<group>.service`
- `all` to restore every group sequentially

`restore` does the following for each group:

1. Stops compose services in the group.
2. Runs `restic restore latest` with the group and machine tags.
3. Runs custom restore hooks, if any.
4. Restores PostgreSQL databases from `/tmp/db-dumps/<group>/`.
5. Runs `postRestoreScript`, if configured.
6. Writes the restore sentinel.
7. Starts the group services again.

## Backup Inputs

For each group, the registry can collect:

- direct filesystem paths
- PostgreSQL database metadata
- custom backup scripts that write into `/tmp/homelab-artifacts/<group>/`

The registry also injects the shared restic repository credentials:

- `restic-repository-password`
- `backup-aws-access-key-id`
- `backup-aws-secret-access-key`

## Operational Notes

- `restic-locked-<group>` owns scheduling for the group.
- `homelab-backup` is the runtime CLI name.
- `homelab.backupJobs.enable = false` disables generated restic backup jobs, locked backup services, and backup timers while keeping restore metadata.
- Old snapshots remain in the repository. New backups use the `backup-v2` tag set.

## Troubleshooting

```bash
systemctl status restic-locked-default.timer
systemctl status restic-locked-default.service
journalctl -u restic-locked-default -n 50
journalctl -u restic-backups-default -n 50
journalctl -u homelab-restore-default -n 50
homelab-backup list
```

If a restore fails, check:

- the generated metadata at `/etc/homelab/services.json`
- PostgreSQL dump files under `/tmp/db-dumps/<group>/`
- custom artifact directories under `/tmp/homelab-artifacts/<group>/`
